# Marriage contexts and guidance

The People relationship-context facet includes eight optional spouse contexts: honeymoon/feeling close, strained/disconnected, actively arguing, repairing after conflict, rebuilding trust, major life transition, considering counseling, and fear/coercion/safety concern. These are explicit selections on `Person.statuses`, not medical temporary episodes, diagnoses or inferred descriptions of a spouse’s feelings. Multiple selections can coexist. Clearing them selects no marriage context; general eligible guidance remains.

The profile editor offers these choices only for spouse profiles and removes incompatible scoped choices if the relationship changes. The server’s existing age/relationship/context matcher selects the same definitions exposed in Help Tree. Adult spouse guidance does not apply to friends, parents or children. The graph and circumstance selector expose these branches and clear the circumstance when the relationship filter changes. **No temporary status** retains its existing meaning: no positive care-episode requirement. It can include marriage-context cards; it does not mean that no relationship context is required.

## Scope and safety

The catalog adds 31 substantive cards and ten source entries. The practical suggestions cover small connection habits, requests, listening, pausing, repair, reliability, transitions and choosing professional support. Distinct descriptions and concrete actions are optional, not a program or promise to extend a honeymoon. There are no interaction ratios, sex quotas, partner scores, divorce predictions or monitoring requirements.

Selecting the safety context suppresses ordinary relationship exercises and conceptual relationship heuristics, including older catalog entries, while retaining individual safety guidance and ethical agency guidance. All new joint-work cards also explicitly exclude the safety context. This is a conservative applicability safeguard, not an abuse assessment. The app does not decide whether someone should leave, contact a spouse or confront them. Immediate danger guidance does not require logging first. No hotline number or automatic escalation is introduced.

IBCT and EFT/EFCT are described as therapist-led approaches, separately from practical Gottman adaptations. Questions about professional fit, safety, costs and access support informed choice. A personal next-step card references the existing `goal` metric; users can create an ordinary private goal through the Goals panel. Counting goals is not completion, clinical improvement or a measure of a spouse’s behavior. No new tracker or sensor was added.

## Direct relationship states

Open **Relationship states** beneath the person’s heading to select multiple applicable states without opening the full profile editor. Saved labels remain visible while collapsed; an empty selection reads **None selected**. Choose **Apply states** to save, **Clear all** then **Apply states** to remove all states, or **Cancel** to discard changes. Spouse-only choices appear only for spouse profiles. Existing unknown or unavailable values are retained unless explicitly cleared. The full profile editor remains available.

Opening the dropdown captures the current states and profile version. Applying sends only `statuses` and `expected_updated_at`, disables editing while saving, and refreshes People queries after success. Failed saves keep the draft and error visible. Each added or removed selection creates a read-only relationship-state entry in History, also available in full history. Entries use the recorded change time, not a retroactively inferred onset. Ended states show their tracked start time when known; states selected before tracking began show an unknown start date. Unchanged selections create no transition. These entries do not create care episodes or measure relationship quality. Manual history entries remain editable. Date backfill and correction controls for system transitions are not included in this iteration.

## Editing and concurrency

Profile PATCH accepts optional `expected_updated_at`. With it, the existing transaction lock compares the saved snapshot to the latest profile and returns HTTP 409 on a mismatch, preserving the newer record. Clients that omit it remain compatible. Profile saves, care-episode writes and metric/module preference writes send the relevant snapshot. Failed saves retain their editor/error state. Profile timestamps advance at least one millisecond so the serialized token changes on each write.

This check prevents a stale editor from silently overwriting another edit; it does not merge drafts automatically. Reload and reconcile before resubmitting. Episode editing still fetches the current episode list and checks whether that episode changed, then uses the freshly fetched profile token to close the race before PATCH.

## Validation and extension points

Shared schemas include optional relationship scope on status options, the optional PATCH concurrency token, and server-owned relationship-state transitions in event read responses. Manual event write schemas do not accept system transitions. REST and MCP reuse the same service; no new route or database column is needed. Tests cover spouse-only matching, every explicit context, empty/omitted selections, legacy context coexistence, safety overlap, Help Tree parity, scoped profile options, graph browsing, and stale-editor rejection against disposable PostgreSQL.
