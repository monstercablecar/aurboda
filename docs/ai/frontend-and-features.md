## Four different meanings of “goal”

| Meaning                   | Storage / behavior                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Global health/metric goal | User settings plus `/goals/progress` and goal history; metric/window/trend semantics.                                                                                                                                                                                                                                                                                                                                                                          |
| Work profile goal         | Work settings with profile-specific goal revisions and effective targets; WorkMetrics derives progress from its recorded data.                                                                                                                                                                                                                                                                                                                                 |
| Person setup goals        | Optional `Person.goals: string[]` entered in [PersonForm](../../apps/web/src/pages/People/PersonForm.tsx). Preference/context text, not independently tracked progress objects.                                                                                                                                                                                                                                                                                |
| Person goal record        | An event with `type: goal`, title/note, optional target date and active/completed/paused status. [Goals panel](../../apps/web/src/pages/People/Goals.tsx) reads `dashboard.goals` and edits through event CRUD. The server includes older/future goal events and treats missing legacy status as active. The legacy Goals metric counts records; optional lifecycle counts separate active/completed/paused entries. Neither is achievement or health scoring. |

Do not silently translate between these concepts or build a fifth goal engine because a similarly named setting exists.

## People privacy and content boundaries

The backend [rules](../../apps/backend/src/services/people-rules.ts) and [catalog](../../apps/backend/src/services/people-catalog.ts) select eligible modules, guidance, reasons and optional metrics. The browser renders those responses, including unavailable states and source links. Catalog content is checked-in, source-linked content, not live external research or generated medical advice; coverage is deliberately incomplete. The server-provided child guide groups play, observations, safety and help; infant profiles use the “Super Baby” label. Source quotations are stored with publisher metadata, separately from paraphrased advice. The care expansion totals 243 catalog records and 86 source entries; these quantities are not evidence of comprehensive coverage or independent clinical review. ACOG pages accessed only through official indexed excerpts are explicitly labeled as such. See [child guide and tracking](../people.md#child-guide-and-useful-optional-tracking) for rolling windows, typed growth/diaper logs and compatibility rules.

Person observations and projections remain private People records, including the dedicated metric projection, rather than globally shareable custom metric/time-series records. Retain this intentional separation when extending tracking. Optional local photos use the constrained local-data flow in [PhotoField](../../apps/web/src/pages/People/PhotoField.tsx); do not introduce remote image fetches. New optional profile fields must tolerate older saved records and cached responses.

## Shared questionnaires: extend without cross-feature leakage

Treatments, Simple Food and Mental Assessments share backend questionnaire resources. A new template can therefore appear outside its intended product unless queries and displays preserve ownership/scope. [Questionnaire choice normalization](../../apps/web/src/pages/Treatments/questionnaire-choices.ts) supports both `config.choices` and legacy `config.options`, including structured choices whose saved value differs from their display label. Never stringify a structured option or replace its stored value with its label.

The exact managed nutrition keys are `simple_food_daily_check`, `simple_food_reaps_v2` and `simple_food_nutrition_gi_intake`. Treatments filters those managed templates, assessments and timeline entries without deleting records; its deep-link notice points to Simple Food. Keep this exact-key behavior when extending scope instead of hiding arbitrary user-created nutrition questionnaires by title.

## Safe extension sequence

1. Find the existing route, shared schema, adapter and backend service for the concept. Follow existing feature ownership rather than creating a parallel store or engine.
2. Add contract fields in `packages/api-spec`; keep persisted/API naming consistent and make additions compatible with older records and cached responses.
3. Put eligibility, recurrence, projections and authorization on the backend. Keep browser formatting and interaction in the existing page/components.
4. Add account-aware query keys and invalidate every affected list, detail and projection. Preserve form state during unrelated query refreshes.
5. Add navigation and Android embedded access where appropriate; check narrow layouts, dark theme, native auth and missing configuration states.
6. Run focused meaningful tests, type checking and the relevant build. For Timeline/query infrastructure changes, include the wider web suite. Update the existing feature documentation and verification record instead of duplicating it here.

Existing [People verification](../people-verification/report.md), [enrichment verification](../people-verification/enrichment.md) and [goals/calendar/questionnaire verification](../people-verification/goals-calendar-questionnaires.md) record prior checks. No application tests were rerun for this documentation-only audit.

### Direct relationship states

The People dashboard places `RelationshipStates.tsx` below the heading, before profile details. Open **Relationship states**, select one or more relationship-scoped choices, and choose **Apply states**. **Clear all** is an explicit draft change; **Cancel** discards it. The collapsed summary shows saved labels or **None selected**. The narrow profile PATCH uses the version captured on opening, keeps unknown saved values, retains errors and drafts on failure, and invalidates the account-scoped People query root on success. Full-profile editing is still supported. See [marriage contexts](../people-marriage.md).

## Relationship-state history

People History renders server-owned `relationship_state` transitions from both dashboard recent activity and full history, with state labels from options and recorded change times. Ended states show the paired tracked start, or explicitly unknown legacy starts. System transitions have no manual edit/delete controls; ordinary entries retain correction. Applying the multi-select Relationship states dropdown invalidates People queries, refreshing history and guidance. No backfill, invented historical dates, relationship-quality score, or system-transition correction UI is provided. See [relationship states](../people-marriage.md#direct-relationship-states).
