# Foghouse Home games

Implemented in the authenticated Home `Dashboard`, separate from its configurable/shared widget data. Explicit The accessible **Tap to play** surface mounts a local iframe; nothing runs automatically and nothing saves automatically. **Save result** records a completed run in Mental Assessments. There is no backend/schema/API change. Android's embedded web Home receives the same UI.

Research-informed personal tracking, not diagnosis, a clinical Corsi equivalent, or a validated PVT. The compact neon arcade keeps instructions, protocol and comparison caveats under **How to play** before starting. During play only the game surface, a small timer/cue, and an exit control remain. There are no diagnostic cutoffs, percentiles, or brain-improvement claims. Sleep, practice, browser, display refresh, device and input method (including touchscreen hardware) can change results; random sequences do not remove practice effects. Compare the same protocol and input mode on the same device.

## Versioned protocols

### Foghouse memory test — `foghouse-memory-forward-v1`

Forward spatial recall using `@jspsych-contrib/plugin-corsi-blocks` 2.0.0. Nine fixed irregular centers, as percentages: `(45,80), (80,92), (20,70), (70,60), (35,50), (8,40), (92,45), (60,25), (47,8)`. Each block is 12% of a square board, capped at 360px and responsive to the iframe viewport. The small shifts from plugin defaults keep edge blocks inside the board.

One two-block unscored practice, followed by lengths 2–9 with exactly two attempts at each length. Advance if either is correct; stop after two failures or after both length-nine trials. Each sequence independently shuffles indices without replacement (Fisher–Yates); sequences can coincidentally repeat between trials/runs. Display: 500ms initial wait, 1000ms highlighted block, 250ms gap. Recall is forward. The plugin ends input on the first wrong block, with 500ms correct/incorrect feedback. A 750ms neutral feedback screen automatically separates trials; no recall response deadline. This feedback/early-ending protocol is custom, not an interchangeable clinical test.

Pointer click/tap only, clearly labeled before starting; there is no claimed keyboard-equivalent recall mode. The reaction task offers a keyboard mode. Instructions are accessible text, but spatial recall itself requires vision and pointer input.

Summaries: longest successfully recalled scored sequence (zero if none), correct scored trials, total scored trials. Practice is retained in raw trials with `practice: true` but excluded from all summaries. Raw records retain expected sequence, response through the first error, plugin cumulative click RTs, correctness and practice status.

### Foghouse reaction test — `foghouse-reaction-3min-v1`

Fixed 180,000ms active protocol, inspired by the brief PVT literature. Independent uniformly sampled integer foreperiods from 1000 through 4000ms; **GO** then accepts the first response for at most 2000ms. Coarse-pointer devices default to tap; desktop defaults to Space, with mode selection in How to play and a launch hint. Keyboard Space uses jsPsych html-keyboard-response; tap/click uses html-button-response. Pointer stimulus RT is measured on click (normally release), whereas early pointer events are detected on pointerdown. Thus pointer and keyboard series should not be treated as equivalent hardware measurements.

Early inputs during the wait are timestamped anticipations and do not shorten it. A post-stimulus RT below 100ms is an anticipation; 100 ≤ RT < 2000ms is valid; a full response window with no valid-timed response is an omission. No study-specific lapse threshold is applied. Waits and response windows are clipped at the deadline. A final curtailed/no-stimulus trial is retained as `boundary`, excluded from omission and valid counts. A response inside the shortened final window remains scoreable even if its callback runs late. RT at/after its permitted window is not valid. Browser scheduling means actual elapsed time may exceed 180 seconds slightly; both actual duration and fixed protocol duration are stored.

Summaries: valid count, anticipations (early events plus sub-100ms responses), omissions, total trials including boundary, 180-second protocol duration, median valid RT, population SD of valid RT, mean reciprocal response speed `mean(1000/RT)` in 1/s. Numeric summaries round to two decimal places. Median/SD/speed remain absent when there are no valid responses. Raw records retain trial start, planned foreperiod, stimulus onset (or null), RT, all early event timestamps and outcome. Times are milliseconds relative to the start except stimulus RT. A 10,000-early-event safety bound cancels an abusive/unusable run rather than truncating it.

## Isolation, lifecycle and persistence

- `apps/web/src/pages/Dashboard/index.tsx` mounts `components/FoghouseGames/index.tsx`. The parent contains controls/results; `foghouse-games.html` and `frame.ts` run only the experiment. Vite has a second build entry, so production receives the HTML and hashed JS/CSS bundles.
- The iframe isolates jsPsych's global listeners/styles and the Corsi plugin's animation-frame/timeouts. Cancellation, hidden document, external focus loss, navigation and unmount remove the iframe; interrupted runs cannot be scored or saved. Parent/child messaging checks exact window source, origin and per-run random token. This is lifecycle isolation, not a security sandbox for untrusted code; all code is locally bundled.
- `protocol.ts` owns randomization, progression, summaries and bounded report serialization. `instruments.ts` defines `mental_foghouse_memory_test_v1` and `mental_foghouse_reaction_test_v1`, appended to the catalog to preserve the first two and existing indexed entries. The `mental_` prefix preserves Treatments' existing exclusion. Metrics have distinct `foghouse_memory_*_v1` and `foghouse_reaction_*_v1` names, never Human Benchmark names.
- `save.ts` reuses Assessments `ensureTemplate`, `entryValues`, `assessmentBody` and existing pharmacology APIs. Every list/create/submit is guarded by the run's session generation and mounted state, including race-recovery list calls after create failure. Guarding follow-on writes prevents old callbacks submitting to a new account. It cannot roll back a request already accepted by the old account's server.
- The parent has an in-flight ref lock and disables saved results. Failed saves retain the result and conditions for explicit retry. Completion time, not save time, is `assessed_at`. Optional conditions are bounded to 2000 characters. Raw protocol/device/trial/summary JSON goes in the existing `report` response; provenance and device fields follow normal assessment storage. This schema's `value` is unknown/JSONB, with no long-text field-length constraint; HTTP JSON limit is 10MB. The feature additionally refuses reports over 100,000 characters with an explicit error, never silent truncation. No localStorage results.
- Save invalidates `['pharmacology']`. History and export are the existing Mental Assessments/pharmacology account data flows. Numeric metrics are normal custom-metric projections and can be deliberately selected elsewhere. The playable iframe/card is not a dashboard widget or included in shared dashboard export. No additional public data exposure is introduced.
- Existing assessment submission has no server idempotency key. The UI prevents simultaneous/known-success duplicate clicks; an ambiguous network failure after server acceptance can still duplicate on retry. Inspect history before retrying an ambiguous response. Adding cross-request idempotency would require a separate API/backend change.

## Sources and software licenses

- [Basner et al., brief PVT](https://pmc.ncbi.nlm.nih.gov/articles/PMC3197786/): three-minute study uses 1–4s waits, unlike standard ten-minute 2–10s. Our two-second omission timeout and presentation are custom; no equivalence claim.
- [Three- versus ten-minute convergent validity](https://pubmed.ncbi.nlm.nih.gov/35242006/): version and outcome-metric dependence limit interchangeability.
- [Computerized Corsi measurement](https://pubmed.ncbi.nlm.nih.gov/25258029/): computerization can alter measured constructs.
- [jsPsych timing accuracy](https://www.jspsych.org/latest/overview/timing-accuracy/) and [browser timing research](https://pmc.ncbi.nlm.nih.gov/articles/PMC8367876/): hardware/software timing limits remain.

Pinned versions: jspsych **8.3.0**, Corsi blocks **2.0.0**, official html-keyboard-response **2.1.0**, html-button-response **2.1.0**. They declare MIT. Actual package metadata/source were inspected, and the jsPsych release-tag license retrieved. Its notice is Copyright (c) 2014–2022 Joshua R. de Leeuw. Corsi's tarball/root had no standalone license; its explicit npm MIT declaration and Josh de Leeuw attribution are retained without inventing a year. Public [third-party notices](../../apps/web/public/foghouse-games-licenses.txt) contain the retrieved jsPsych license, standard MIT text for Corsi, and bundled auto-bind, random-words and seedrandom notices. ## Verification

`protocol.test.ts`: no-replacement randomization, wait endpoints, adaptive progression/practice exclusion, boundaries/omissions/anticipations, median/SD/reciprocal speed, no-valid-data behavior, isolated catalog keys and oversized-report rejection. `save.test.ts`: completion timestamp/raw provenance, retry preservation, account switch at list/create/recovery and unmount follow-on-write guards. `index.test.tsx`: opt-in iframe, cancellation/late-message rejection, visibility/unmount teardown, explicit-save-only, duplicate lock, retry, saved-state behavior and terminal completion winning over teardown focus events. `frame.test.ts` runs the actual jsPsych timeline under a virtual clock: three-minute completion with a real keyboard response, omissions and deadline boundary; interruption discards the run; standalone navigation never starts a game.

Focused tests plus the existing Assessments model suite: **36 passed**. Typecheck and production build passed. Scoped lint reports zero warnings/errors. The build emits the separate frame HTML, bundle and public notices. The full web run passed 179 suites / 1673 tests; its sole failing test could not spawn a child Node process (EPERM), and the affected five-test DST suite passed when rerun with subprocess access. No Android build or physical-device timing validation was performed. Parent additionally exercised synthetic template → submit → fetch roundtrips against the real pharmacology HTTP routes with a disposable database, preserving both games' summaries, raw report and completion time. This is API verification, not physical reaction-timing validation. Browser observations and final build checks are recorded in the task report; no deployment is implied.

Browser QA on the final neon layout verified desktop launch and memory practice with automatic transitions, pointer GO responses, Escape cancellation, and a 390×844 mobile launch/board without horizontal overflow. The earlier memory run completed two scored trials and explicitly saved successfully with the Saved control disabled afterward. Independent SQL inspection verified the two distinct projected metric sets. No production deployment was performed by the implementer.
