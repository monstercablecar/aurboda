# Upstream integration audit — November 17, 2026

## Scope and method

The GitHub default `develop` branch is 233 commits behind upstream `develop`. Production uses `feat/foghouse-customizations` at `88dc3d959e4866561945ed5f4a756e0fe953237b`; that branch lacks 251 upstream commits. This inventory covers the union: every one of the 233 advertised commits plus 18 earlier commits absent from the customization branch. The upstream snapshot is `c3bd536353759ef3a09dad53348a10614f7322c8`.

The 251 entries comprise 138 non-merge changes and 113 merges. Every entry was inventoried by parents, changed paths and test changes. Every non-merge patch was scanned for migration, authentication, privacy, dependency and publication impact; integration conflicts and security boundaries received focused source inspection. Of the merge entries, 111 have no remerge diff; two have conflict resolutions, which were inspected separately. This is a compatibility/adoption audit, not a claim of an independent line-by-line security audit of every upstream implementation.

## Adoption decisions

- Merge upstream history without rebasing. Keep all existing custom feature registrations and private storage.
- Adopt catalogs, strength logging, muscle history, improved analysis/statistics, sleep debt, timeline ranges, segments, barcode lookup/scanning, lab imports, dashboard improvements and federation reliability fixes.
- Preserve stricter structural-only audit logging and newer fork dependency versions. Suppress raw errors from the new Garmin push endpoint.
- Keep native Tasks, Family/People, Work, Journal, Resources, Treatments, assessments/games, CPAP, onboarding, page visibility, browser push and account-session protections.
- Keep email/SMTP, OIDC providers, Garmin Developer Program and Home Assistant unconfigured unless separately set up. Code support alone does not connect an account or transmit its data.
- Email recovery does not revoke existing bearer sessions. Leave it unconfigured for this release; do not present it as a compromised-session remedy.
- Keep official APK/container publication restricted to fiddur/aurboda. Native source validation does not distribute a custom APK.
- Refresh the host nginx overlay from the new nginx.conf so Garmin routing and current hardening both survive. Preserve resource limits and validate backups before cutover.

## Merge compatibility

31 conflicted files were combined explicitly. Shared schemas include custom settings and new upstream fields. Both private tables and notification tables remain registered. Resources and account email/OIDC central storage coexist. Sleep retains naps, check-ins, wake-date attribution and history while adding sleep-debt displays. Timeline retains private future Family dates and session navigation while adding daily metrics and range presets. Navigation keeps page descriptions/visibility and adopts new destinations in source-card order. New OIDC/recovery auth assignments are fenced against account changes.

## Migration and rollback constraints

Startup includes data conversions as well as additive schema changes. In particular, legacy single-lift activities become strength-training sets; unreferenced built-in lift definitions are deleted and referenced definitions become custom types. Image rollback does not reverse these transformations. Deployment requires a synthetic upgrade and old-image compatibility test covering references and overlapping sessions, a matched pre-upgrade backup, and private verification of schema fingerprints and startup maintenance completion without migration errors. Database discovery must occur after pausing application writes.
