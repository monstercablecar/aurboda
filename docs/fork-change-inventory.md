# Aurboda fork changes and remaining work

Status recorded November 15, 2026. This is the feature-level inventory of our changes, their purpose, what was deployed, and what still needs work. Fredrik Liljegren created Aurboda; its original platform, integrations, Android companion, authorship, and licenses remain upstream work.

Early custom development was published as a combined snapshot rather than individual public feature commits. This inventory therefore groups changes by behavior. The [original file inventory](fork-file-inventory.md) records the initial publication; [fork scope](foghouse-fork.md) and the linked feature guides provide implementation details. Reasons below describe the practical purpose of each change, not a verbatim history of every request.

## Verified deployment

The local installation was deployed at merge commit `9fb3ef9941a67b5caf4f2581a00e515442c3f61f` from `feat/foghouse-customizations`, through [PR #12](https://github.com/monstercablecar/aurboda/pull/12). Its source tree matches the reviewed PR head `6822c713949e212bb70412fbb16877e0e99ba83b`.

- All pre-merge checks passed: 7,119 backend tests, 1,969 web tests, Android tests/build, type/lint checks, build, and secret scanning.
- [Post-merge CI](https://github.com/monstercablecar/aurboda/actions/runs/43763433688) and [post-merge secret scanning](https://github.com/monstercablecar/aurboda/actions/runs/43763433682) also completed successfully. Nothing remained pending.
- Local and public status reported the exact deployed commit. Page-shell checks, unauthenticated private-API rejection, and container health checks passed.
- Validated database and Resources backups and the previous image were retained. Private operational records and backup contents remain outside Git.

“Deployed” below means included in that server/web release. It does not mean every optional feature is enabled for every account, or that every interaction was tested on a physical device. Browser reminders need configuration and permission; dashboard presets need installation. Android source changes are included in the repository and validated by CI, but no custom APK has been distributed. This is a dated deployment record, not a claim about future server state.

## Remaining work and priorities

The original audit found no confirmed exploitable P0 application issue or cross-user disclosure. Dependency remediation and credential-safe logging are complete. Remaining audit findings below have not been fixed by the security release.

| Priority                   | Issue                                                                                                                                                                | Next action and reason                                                                                                                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1                          | Journal can lose offline writing when browser persistence fails.                                                                                                     | Track durability separately from online/save status; retain storage-error warnings, make leave prompts truthful, and offer copy/download recovery. Test quota exhaustion, denied storage, navigation, reload, and successful retry. |
| 2                          | Corrupt or blocked saved-auth storage can prevent startup.                                                                                                           | Guard and validate initial/cross-tab reads and writes; fall back to usable signed-out state while preserving native-bridge behavior and account fencing. Require security review.                                                   |
| 3                          | Initial settings failure hides onboarding; missing clipboard support can throw.                                                                                      | Show initial-load retry and handle missing APIs as well as rejected promises. Preserve dismissed/completed progress.                                                                                                                |
| 4                          | Mobile drawer lacks a complete focus lifecycle.                                                                                                                      | Remove closed controls from keyboard navigation; manage entry, containment, Escape/backdrop dismissal, and focus return. Validate narrow widths and zoom in a real browser.                                                         |
| 5                          | Feature Control can overwrite another client's choices.                                                                                                              | Apply per-page operations under a lock or use revision/conflict checks. Test two clients and retain unknown future keys and Settings recovery.                                                                                      |
| Planned security design    | General bearer tokens have no per-session expiry/revocation; logout does not invalidate a copied token.                                                              | Agree on a lifetime/revocation policy that preserves Android and agent compatibility before implementing it. This is a design risk, not a demonstrated bypass.                                                                      |
| Portability                | Setup instructions and native defaults retain a host-specific server.                                                                                                | Derive URLs from validated instance configuration; test multiple origins, proxy API paths, and saved server choices.                                                                                                                |
| Calendar correctness       | ICS ingestion lacks full recurrence/exception and remote deletion/cancellation reconciliation.                                                                       | Clearly document current limits or implement bounded occurrence expansion and provenance-aware reconciliation with DST and UID tests.                                                                                               |
| Performance                | People dashboards load complete histories per card; the main web bundle remains sizable.                                                                             | Benchmark synthetic account sizes and cold loads first, then consider lightweight summaries, pagination, and safe projection updates.                                                                                               |
| Documentation and upstream | Older maps describe obsolete checkouts/pending work; broad upstream integration overlaps custom navigation, schemas, auth, and contracts.                            | Refresh the current branch/checkout map and prepare a subsystem inventory before a separately authorized upstream merge. Historical upstream-ahead counts are not current status.                                                   |
| Automated UI coverage      | Unit/DOM tests do not cover real mobile focus, layout, or complete account-switch flows.                                                                             | Add a small synthetic browser suite for onboarding, Settings, hide/unhide, Journal, and account switching.                                                                                                                          |
| Device parity              | Android Journal microphone permission bridging and physical-device upload/download/print behavior remain incomplete or unverified.                                   | Validate and address device-specific gaps; do not describe CI compilation as physical-device parity.                                                                                                                                |
| Operational assurance      | Backup readability was validated, but off-site copies, encryption, scheduled coverage, and a full recovery drill were not established by this work.                  | Verify those operational properties and rehearse recovery using an isolated environment.                                                                                                                                            |
| Other security semantics   | MCP mutation-prefix classification is fragile; get_task_board can initialize defaults under a read-only usage channel. Resources preview sessions are process-local. | Define strict read-only behavior and test tool classification; validate preview expiry/revocation and routing behavior before scaling to multiple replicas.                                                                         |

Start with Journal durability, then startup storage resilience, followed by onboarding recovery, mobile focus, and concurrent preferences. Keep changes focused and preserve the existing review, test, and deployment gates.
