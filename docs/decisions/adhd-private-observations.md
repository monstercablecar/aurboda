# ADHD private observations (2026-11-25)

Status: accepted after bounded architecture review; mandatory safeguards below.

Use unified `check_ins` as the only canonical store for all new ADHD questionnaire values. Its form/version snapshots, output opt-out, request ledger and transaction-scoped dependencies are mature enough for real persistence. ADHD metadata contains typed item missingness, scope, precision, source/timezone, target snapshot and phase; it references canonical answer IDs and never copies values. Legacy assessments are read through an explicit source/version adapter, never migrated or joined to time-series projections as independent observations.

Add nullable `owner_scope` to check-in forms. ADHD-created immutable forms carry `adhd`; generic form discovery excludes them and generic mutations reject them. Internal ADHD submissions use `scopedCheckInDeps` and `submitCheckInLocked` on the same transaction as domain transitions, with expected version and output-mode validation. The November 26 user instruction enables ordinary private numeric metric projections by default for new answers. Old disabled form/answer snapshots remain immutable and are not backfilled. New answers always use immutable metric-enabled form variants, without an ADHD-specific output preference. They use the existing transaction-scoped projection ownership ledger; canonical answers remain the only analysis samples. Do not masquerade task/experiment links as activity links. Managed form versions cannot be silently edited through generic APIs.

Add account-local domain tables for settings, hypothesis versions/evidence references, immutable protocols, opportunities/attempts, observation metadata, invitations, saved recipes/reviews and content-free idempotent command digests. JSONB stores bounded validated snapshots and semantic metadata, not copied task/journal/medication/sleep objects. One transaction-wide ADHD advisory lock provides serial assignment/state transitions and request-key conflict detection; CAS revisions prevent lost edits. All references are resolved in the authenticated account database; native task/journal IDs need owner-local existence checks. No account selector appears in bodies.

Default protocols are seven-day feasibility pilots with at most one opportunity per frozen local day and server-randomized balanced pairs; target/endpoint/eligibility precede condition reveal. First successful displayed acknowledgement freezes exposure/action-window start, independently of assigned/accepted/used/outcome state. Outcomes distinguish known false from unrecorded and session ending never completes a native task. Protocol changes create new records; reminder preference edits cannot rewrite assignments.

The existing notification coordinator is the sole scheduler (inspect actual cadence). Disabled-by-default generic reminders use frozen invitation windows, quiet/protected windows, expiry, bounded daily budget, and authenticated lifecycle actions. Pause suppresses open invitations and clears actions immediately; resuming creates no backlog. Private export includes canonical observations, all immutable definitions and missingness. Database dump continues to include all tables; deletion erases domain content and canonical answers through an explicit account-local transaction.

Frontend uses the fenced shared Axios client and session-bound QueryClient. Drafts/pending command request IDs are account/session scoped, expire, and are cleared on logout/switch. Pending responses do not declare success; identical uncertain retries reuse the same request. No-log help performs no persistence, analytics or external calls. Pure deterministic analysis excludes retrospective/uncertain timestamps from hour plots and reports observation/day coverage, missingness and exact denominators without causal labels.

No new external AI, sharing callback, activity generation, task manager or worker. Existing user metric/sharing preferences continue to govern ordinary private numeric projections. Each answered item has a stable versioned metric name, score unit, construct/recall/anchor metadata and original observation time. Retrospective/day/uncertain/imported samples use a distinct `_reflection` metric suffix; incompatible time scopes are not mixed with momentary metrics. Skipped and inapplicable items produce no point. Metric/time or incompatible-unit collisions return 409 and roll back the whole command. Deletion removes only owned, unmodified projected points through existing compare-and-swap mechanics; user-edited points survive. No separate activity or aggregate severity/readiness score is produced. Official ASRS links are sufficient; no clinical scale reproduction. Native `/adhd?embed=1` navigation may be added to source but no APK is built/published without separate authorization.

Review safeguards: generic answers as well as forms are scoped. Managed reads/mutations cannot bypass the domain. All refusals throw before the outer transaction commits. Lock order is account ADHD lock, forms, then canonical request lock. Completed identical retries resolve before CAS/version checks. Domain requests bind operation plus a normalized payload digest; raw request content is never copied into that ledger. Canonical request payloads are erased with deleted answers. SQL uniqueness protects daily assignments and answer links. Draft dispatch captures session generation before awaits and checks again before retries. Pause/expiry are rechecked by producer and actions under the same lock.

Mixed-version release condition: do not accept ADHD writes while any older server can serve unscoped generic check-in APIs/MCP. Rollback must retain the managed-form guards or explicitly restore a matched prefeature account backup under an approved data-loss plan.

## November 26 interface revision

The primary flow is action-first: barrier chips, at most two support choices, then one focused action. Checks show one exact instrument question at a time with full anchors and explicit skip/back navigation. Experiment setup, opportunity, displayed support, reflection and review are distinct steps; raw ledgers and methodology use progressive disclosure. Toolkit sections and evidence are separate from the finite card grid. Flat cyan/magenta accents support hierarchy in light and dark themes without animation, streaks or scores. Account fences, retry identity, drafts and automatic first-display acknowledgement are retained.

The later interface instruction removes all feature-specific deletion, draft-discard, export and privacy/output controls from the ADHD page. Standard Aurboda data controls remain the user-facing management surface; internal lifecycle deletion/CAS protections and export service remain supported. Pause and withdrawal control participation, not data removal.
