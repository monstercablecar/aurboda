# ADHD: optional support and private personal experiments

This page helps choose a small next action, including deliberate recovery, connection, play, deferral or stopping. Tracking, screening and experiments are optional. It does not diagnose ADHD, infer dopamine or reward favorable observations. App visits, logging volume and streaks are not success measures.

## Use it today

Open **ADHD → Now**, choose one barrier, and use one of at most two concrete supports. Choosing or browsing a support creates no behavioral record. You can leave immediately. **Save this action/session** explicitly opts into a private record; temporary labels create no task-board item. A saved session and task completion are separate operations. Recording a session outcome never completes a task or creates a recurring successor.

The optional check offers Tiny (energy/clarity or explicitly chosen task-interest/start-ease), Core (four with a target), Full (six), or a separately chosen deeper pack. Target and phase remain visible. With no task, task items are not applicable; during ongoing work, anticipated initiation ease is not applicable. Skipped items do not block help or assignment. Values are never carried forward or inferred from sensors, prose or task completion.

**Experiments** creates an explicitly chosen seven-day feasibility pilot, or a fourteen-day plan. Freeze a narrow safe activity class, acceptable awake window, timezone, benefit threshold and strain guardrail. Choose a real safe interruptible opportunity, endpoint, ten available minutes and acceptance of either method before reveal. No readiness cutoff excludes low interest or difficult anticipated starts. At most one assigned opportunity per frozen local day; refresh never rerolls. Unavailable and declined opportunities are recorded separately, without a condition.

Prepared starter versus usual approach is genuinely randomized in balanced pairs: first allocation is a server cryptographic fair coin, second is the complementary arm. The ledger stores block and conditional allocation probability (0/1 for the complementary assignment, 0.5 for the first). This is random permuted pairs, not alternating deterministic allocation and not adaptive allocation. Usual approach receives the same endpoint, measurement and visual attention without the intervention's detailed starter exercise.

The first rendered support triggers an account-fenced, retry-stable display acknowledgement. `assigned_at`, first display, server receipt, material delay and exposure uncertainty are separate. A plausible first-display timestamp cannot precede assignment and is bounded by server receipt; uncertain client timing stays labeled. An assigned but unexposed condition is not a timed failure. Reading and setup count in the same five-minute window for both arms; a timer, generated plan or page visit is not evidence of actual work.

Accepting a method, declining it and reporting actual support use are separate controls. Declining and later starting can both be true. The default follow-up asks actual start (with categorical timing) and endpoint, with the same strain item only when the frozen pilot requests it. Interruption before/after start and another chosen action remain independent. Outcomes can be unknown. Stop-cue pilots share a finite endpoint and additionally report overrun and willingness to reuse. No medication, supplements, sleep deprivation or risky-activity comparisons are provided.

Review at the pilot's expiration; there is no automatic extension. A new plan is a new versioned record. Immediate global pause and pilot pause/withdrawal remain available. Paused history is retained; returning creates no catch-up queue or missed-day debt. A pause does not prohibit an explicitly chosen private reflection or later outcome correction.

**Patterns** shows raw compatible observations, gaps/missingness, broad hour bins with observation and distinct-day counts, same-target interest/start ease, energy/pleasantness, source-separated legacy records, and editable hypothesis versions/evidence references. It does not choose a permanent best hour or manufacture an insight from sparse data. Hypothesis statuses are user-controlled workflow descriptions, not calibrated probabilities. No automatic state tags are generated; user descriptions remain separate from algorithms. Core alone cannot establish contentment, pressured focus or flexible stopping.

**Toolkit** contains twelve finite strategies with exact stable IDs/versions, costs, scoped evidence and sources, plus reusable friction/stop recipes and an original weekly review. Saved recipes can start explicitly recorded sessions. Time estimation compares an optional prediction with confirmed self-reported elapsed times; interruptions remain visible and elapsed session time is not verified work time. Extra cognitive/performance tasks are deliberately omitted because their device/scoring validity has not been established for this feature.

## Data ownership and contracts

See [the architecture decision](../decisions/adhd-private-observations.md). Shared schemas in `packages/api-spec/src/schemas/adhd.ts` are the sole REST/MCP contract. `services/adhd.ts` owns domain transitions, `db/adhd.ts` storage primitives, `services/adhd-observations.ts` the canonical adapter, `adhd-analysis.ts` deterministic time/count functions and `adhd-catalog.ts` versioned definitions. Web imports contract types only.

All new questionnaire values live only in unified `check_ins`, linked to immutable private `check_in_forms` v1 snapshots with `owner_scope='adhd'`. Metadata stores item status but not a second copy of values; API serialization joins canonical values. Generic form/answer discovery, reads, edits, deletes, restores and adherence reject managed forms. New numeric answers appear in ordinary Aurboda Metrics. Each answered numeric item projects through ordinary private metrics with source ownership, score units, original time and full construct/anchor metadata. Old disabled snapshots are immutable and are never backfilled. Retrospective/day/uncertain/imported samples use separate `_reflection` metrics. Skipped/inapplicable items create no point; metric/time and incompatible-unit collisions refuse atomically rather than overwrite. ADHD analyses count canonical answers once. Deleting a response removes its owned unmodified points; independently edited points remain. Existing sharing settings govern ordinary metrics; this feature does not enable external sharing, AI forwarding or activity generation.

Account-local additive tables hold settings, versioned domain records, canonical-answer metadata and a request ledger. Protocols freeze eligibility, outcomes, question snapshots/version, horizon, burden and timezone. Target snapshots intentionally preserve historical meaning when a task is renamed. Domain references use actual task/project/journal IDs in the authenticated account database; no task ID is passed as an activity ID. Main-sleep linkage currently remains unknown rather than selecting the latest nap as main sleep.

All write transitions hold the ADHD account advisory lock before form locks. Canonical writes, metadata, assignment/CAS and notification transitions use one transaction/client; every refusal throws before commit. SQL uniqueness additionally protects one active protocol, one assignment per protocol/local day, one invitation per frozen local slot and one metadata row per canonical answer. Identical completed retries resolve before revision/version checks; changed normalized content with the same request key returns 409. The request ledger stores a SHA-256 digest and structural IDs, never copied answers or task labels.

Every ID lookup is account-scoped. REST/MCP call the same services; `set_adhd` uses the existing mutating-tool classification and read-only gate. Tools must act only on explicit user instructions and must never invent observations or silently enroll someone.

Browser drafts and pending request IDs expire after 24 hours, are account-scoped, and clear on logout/account/token transition. Dispatch and delayed continuations capture the session generation before work. Same-account reload retains an uncertain key. A missing response does not prove rollback; retry keeps the exact request. Definitive 4xx refusal clears only pending status, retains the draft, and shows an error. Saved appears only after server confirmation. An accepted server write cannot be undone merely by canceling its HTTP request.

Explicit observation deletion removes its canonical answer and metadata and clears canonical request payloads. Pilot/attempt deletion also removes linked canonical answers. Referencing private hypothesis evidence is removed, including descendant observations, prior hypothesis versions and frozen protocol hypothesis snapshots; unrelated evidence remains. Command digests remain as content-free idempotency tombstones. Deleting an assigned attempt erases its target, answers and outcome but keeps a structural assignment reservation (condition, frozen day/block/probability and IDs) so deletion cannot reroll or erase the assigned denominator. It appears explicitly as deleted content with an unrecorded outcome. Deleting the whole pilot removes its reservations too. The internal lifecycle API can delete a completed observation before recording a replacement with its actual assessed time/scope; completed attempt outcomes similarly require an explicit replacement rather than rewriting a frozen assignment. Backups, browser history and downloaded exports have independent retention.

## Instruments and missingness

The catalog in `adhd-catalog.ts`, returned by the API and shown in page details, defines every custom item: exact wording, full anchors, construct, recall, applicability, version and intended decision. `energy_now_v1`, `clarity_now_v1`, `target_interest_v1`, `target_start_ease_v1`, `strain_now_v1`, and `pleasantness_now_v1` retain the brief's exact wording and anchors. Focused items cover next action (No/Partly/Yes), choice, task demand, switching, physical fatigue and explicitly chosen-domain creative appetite. They are original tracking items, not clinical scales or a combined ADHD/readiness score.

Items are answered/skipped/not_asked/not_applicable; only answered items have canonical values. The general missingness contract preserves valid zero/false; current rating instruments accept only their declared anchored range. Observed and recorded timestamps are independent. Source, scope, original IANA zone/offset and minute/hour/date/uncertain precision are retained. Date/uncertain, day/retrospective and imported values do not populate momentary hour comparisons. The manual datetime field explicitly uses browser-local time before conversion to UTC; account-selected display-zone charts are labeled separately.

Legacy reads use assessment and response identities and frozen template/question versions, with no numeric time-series projection joins. Legacy scales remain separate, scope is labeled unreviewed, and none are pooled with new task-specific measures. Old motivation is not target interest; fatigue is never inverted into energy. No personal history or examples from the implementation brief are seeded in user accounts.

Arm tables show assigned opportunities, exposure, any explicitly reported actual support use, declines, known within-window starts/nonstarts, interruptions, distinct days and missing outcomes. A known-outcome fraction always appears beside assigned totals and missingness; it is not labeled intention-to-treat. Unknown is not failure or random missingness. Missing paired strain observations say **Strain tradeoff not assessed**, never a passed guardrail. More minutes is not inherently better; no p-values or automated causal conclusion are produced. Repeated samples in one day are not independent days.

## Reminders and timing

Reminders start disabled. The existing notification coordinator runs once per minute; no new worker, cron or push stack was created. User-configured times resolve into frozen UTC windows with local intent, offset and preference revision. Current local quiet hours and the frozen protocol awake window are rechecked at enqueue and immediately before a queued browser send; crossing either boundary suppresses the invitation and expires pending deliveries, including snoozes/retries. DST gaps/folds are suppressed using Temporal's reject disambiguation. Overnight windows work. Quiet/protected sleep windows take priority. Expired windows are unrecorded; there is no backlog replay. Global pause and completion suppress open windows and immediately mark corresponding notifications read/clear actions. Snooze stays within the original 30-minute window and can produce a bounded subsequent notification.

Invitation states distinguish planned, delivery attempted, opened (explicitly acknowledged), completed, explicitly skipped, snoozed, expired/unrecorded and suppressed. Stored browser push is not proof of delivery or opening. Notifications use generic lock-screen text and contain no mental-state or task detail. Authenticated page lifecycle commands recheck account, CAS, expiry and pause under the same lock. Provider sends already in flight cannot be recalled. Existing browser push/VAPID configuration and user subscription are still required for push; in-app invitation history works independently.

## Evidence boundaries

Checked official sources include [CDC presentations](https://www.cdc.gov/adhd/signs-symptoms/index.html), [NICE environmental modifications/structured support](https://www.nice.org.uk/guidance/ng87/chapter/recommendations), [Safren's therapist-delivered CBT trial](https://pubmed.ncbi.nlm.nih.gov/20736471/), [NAS's limited/contested demand-avoidance evidence](https://www.autism.org.uk/advice-and-guidance/behaviour/demand-avoidance), and the supplied [CENT reporting reference](https://doi.org/10.1136/bmj.h1793) (full paper not independently retrieved). An app borrowing planning skills does not inherit the clinical treatment's validation. The seven-day pilot is not automatically a clinical N-of-1 trial.

Body-doubling findings differ across a [conference reading-task study](https://www.ccsc.org/centralplains/2025/talks/talk-poster16/) and [small VR preprint](https://arxiv.org/abs/2509.12153). [Music pilot evidence](https://pubmed.ncbi.nlm.nih.gov/31156516/) concerns current mood, not general work performance. The supplied [child implementation-intention research](https://doi.org/10.1007/s10608-007-9150-1) is indirect for an adult app; the supplied [general reactance research](https://doi.org/10.1080/03637750500111815) is not proof of an ADHD mechanism. Rewards are finite useful feedback, never a variable-reward feed or favorable-rating incentive.

The page links the [official ASRS v1.1 six-item PDF](https://www.hcp.med.harvard.edu/ncs//ftpdir/adhd/6Q_ASRS_English.pdf) and [current NYU use terms](https://license.tov.med.nyu.edu/product/asrs6Qscreener) rather than reproducing/scoring a screener. Six-month screening recall is kept separate from momentary tracking. Screening is optional and not diagnostic or a condition of access.

To add a strategy, extend the stable versioned catalog with its target barrier, finite steps/end, expected benefit, possible cost, scoped literature category/sources and optional existing item pack. Do not create another response store or silently change instrument wording. Changing an active trial's meaning requires a new immutable protocol/version.

## Migration, export, release and rollback

Before deployment:

1. Verify the actual running source/image and preserve existing customizations.
2. Run format, type/lint, backend/web tests and the required security review on the exact candidate. Regenerate OpenAPI/TypeScript/Kotlin with `pnpm generate`; an Android SDK build is a distinct gate.
3. Take fresh matched database, role and file-storage backups with checksums; retain the current immutable image and configuration/volume identity.
4. Schema changes are additive/idempotent and apply through normal schema initialization. Existing health/questionnaire rows are not reinterpreted. An idempotent compatibility repair removes duplicated pre-release `outcome.strain` JSON while retaining canonical answers.
5. Ensure all serving processes have managed-form guards before the first ADHD write. Stop older unguarded processes before enabling the writable page; a rolling cluster needs a coordinated guard-first rollout.
6. Verify account isolation, anonymous refusal, saved/retry/assignment behavior, notification suppression, standard metric integration and owned projection deletion. Compare existing data and settings according to the deployment's preservation procedure.

For rollback after new ADHD data exists, retain all additive tables and use a compatibility candidate with managed-form guards (hide the ADHD page if desired). Simply starting an older image can expose managed forms through its generic check-in UI/API/MCP. Do not drop tables or restore a prefeature backup without a separately approved data-loss plan; first export/backup new private data. Existing matched image/database/file recovery procedures remain authoritative.

Authenticated `GET /adhd/export` and `export_adhd` provide JSON export; no extra export, deletion or privacy controls are added to the ADHD page. It includes current canonical values/missingness, protocol/question snapshots, hypotheses/versions/evidence, assignments/exposure/use/outcomes, invitations, recipes, reviews, provenance and source-separated legacy history. Ordinary full account pg_dump includes all additive tables; disposable PostgreSQL tests exercise actual dump/restore.

Web `/adhd` and `/adhd?embed=1` use existing authentication/themes/session boundary. Android source adds the embedded route to More. An installed APK's native menu does not change with server deployment; use the web route or a separately authorized future native release. No physical phone/APK claim is made.

Start the seven-day pilot only if useful: use no-log help first, choose a narrow safe task class and two acceptable methods, activate once, take at most one real opportunity per day, and review feasibility at expiration. Reminders can stay off. Wrong hypotheses, no benefit, or deciding to track less are valid outcomes.

Kotlin generation keeps dynamic ADHD command envelopes as `JsonObject`, scalar answer unions as `JsonElement`, and arbitrary record/legacy maps as JSON values through the existing reproducible fixup script. Static models remain generated/typed. YAML uses 1.1-compatible quoting so string options such as yes/no/off cannot silently become booleans in the generator. The embedded native screen does not deserialize these envelopes today; an Android SDK build remains a separate unverified gate.
